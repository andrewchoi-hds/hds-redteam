# RFC: Housing 실시간 재고 동기화 아키텍처

- 상태: 제안 (Proposed)
- 작성: 플랫폼팀
- 대상: V1.2 — 핸디즈 재고를 실시간에 가깝게 반영

## 1. 배경

현재 V1은 10분 주기 폴링으로 핸디즈 Plott 매물·재고를 가져온다. 인기 매물에서 "예약 가능"으로 보였다가 결제 단계에서 품절되는 사례가 늘고 있다. 이 RFC는 재고 정합성을 초 단위로 좁히는 방안을 제안한다.

## 2. 목표

- 재고 반영 지연을 10분 → 5초 이내로 단축
- 결제 진입 시점의 재고 정확도 99.9%
- 기존 검색·예약 API 인터페이스 변경 없음

## 3. 제안 설계

### 3.1 이벤트 수신

- 핸디즈가 재고 변경 시 우리 웹훅으로 push (기존 계약 이벤트 웹훅 재사용)
- 웹훅 수신 즉시 우리 Postgres `listings.available` 컬럼을 UPDATE

### 3.2 결제 진입 시 실시간 확인

- 사용자가 결제 진입하면 핸디즈 재고 조회 API를 **동기 호출**해 최종 확인
- 응답이 "가능"이면 진행, 아니면 "품절" 안내

### 3.3 재고 락

- 결제 진입 사용자에 대해 애플리케이션 메모리(Node 프로세스)에 `Map<roomId, userId>` 형태로 락을 잡는다
- 결제 완료 또는 타이머 만료 시 락 해제

### 3.4 캐시

- 검색 결과는 Redis에 5초 TTL로 캐싱
- 재고 변경 웹훅 수신 시 해당 매물 캐시를 삭제

## 4. 대안

- 폴링 주기를 1분으로 단축: 부하만 늘고 근본 해결 아님. 기각.

## 5. 배포

- 기존 API 서버에 웹훅 핸들러와 동기 확인 로직을 추가 배포
- 기능 플래그 없이 전체 트래픽에 즉시 적용

## 6. 관측

- 웹훅 수신 건수를 로그로 남긴다
